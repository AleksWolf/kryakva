# Пульт серв

Сервер на Python и страница в браузере. Слева — 3D-модель утки, она повторяет положения серв; справа — 15 слайдеров по ID
с живым чтением положения, напряжения, температуры, нагрузки, тока и битов состояния. Основа — `servo-web` из
fanhao375/microduck-replica (Apache-2.0), модель — своя.

## Подключение

- С компьютера (Windows или Linux): UC-01 по USB-C, порт — COM в Windows, `/dev/ttyUSB0` в Linux;
  питание серв 7.4 В — в клеммник UC-01.
- На утке: Zero 3W по своему порту серв `/dev/ttyS2` (UART2, пины 8/10), питание — от батареи утки.

## Запуск на компьютере

```
pip install -r requirements.txt
python server.py --port COM5                                   # Windows; номер порта — в диспетчере устройств
python server.py --port /dev/ttyUSB0                           # Linux
python server.py --fake                                        # без серв: виртуальные сервы, посмотреть интерфейс
```

Страница — `http://127.0.0.1:8080`. Порт держит одна программа: пульт и `servo_report.py` одновременно не работают.

## Запуск на утке

Пакеты (один раз):

```
sudo apt-get install -y python3-starlette python3-uvicorn python3-websockets python3-serial
```

Папку `software/servo_console` скопировать на плату в `/home/duck/servo_console`.

Порт серв держит robotd, поэтому его надо остановить. При остановке robotd снимает момент со всех серв, и утка обмякает.
Останавливать только лежащую утку:

```
sudo systemctl stop padd robotd
cp -r /home/duck/servo_console /tmp/ && cd /tmp/servo_console
python3 server.py --port /dev/ttyS2
```

Пульт запускается из копии в `/tmp`: его журнал `logs/` пишется в ОЗУ, а не на карту. Страница — `http://<адрес Zero>:8080`.
Направления, изменённые на утке, лежат в этой копии; чтобы их сохранить, скопировать `directions.json`
обратно в `/home/duck/servo_console`. После работы — Ctrl+C и `sudo systemctl start robotd padd`.

Одновременно с пультом на утке не запускать пульт на компьютере через USB-C UC-01: шина одна.

## Страница

Язык — английский или русский, переключатель EN | RU вверху; выбор запоминается в браузере.

Верх: связь, на линии N/15, частота опроса, напряжение шины; выбор порта и «Подключить».
Кнопки: момент на всех вкл/выкл; «Слайдеры = текущие положения» — до включения момента, иначе сервы прыгнут к старым целям;
«Все в ноль (2048)» — ноги прямые, голова прямо, только после калибровки нулей; «Оживить голову», «Сканировать».

У каждой сервы: слайдер цели (0–4095, 2048 = ноль, 11.4 отсчёта на градус; жёлтая риска — фактическое положение), угол, напряжение,
температура, нагрузка, ток, флажок момента, кнопка знака направления. Панели ниже: калибровка нуля, одна серва (регистры 0–86,
перезагрузка, смена ID), движение (время перехода, ускорение, стоп), тест цикла шины, журнал.

Слайдеры ограничены пределами суставов из модели; сервер обрезает любую цель по тем же пределам и пишет об этом в журнал.

## Направления

`directions.json` — знак каждой сервы; влияет только на 3D, саму серву не трогает. После сборки проверить каждый сустав:
+10° на слайдере — серва и 3D идут в одну сторону. Если нет — кнопка ± у этой сервы.

## Другие скрипты

- `new_servo.py` — ID и ноль новой сервы, порядок — [hardware/servo_setup.md](../../hardware/servo_setup.ru.md).
- `servo_report.py --port COMx` — чтение регистров всех серв, ничего не пишет; отчёт в `logs/`.
